# Job Platform

Веб-платформа для поиска вакансий и взаимодействия между работодателями и соискателями.

Проект разработан на Django с использованием PostgreSQL и Django REST Framework.

## Основные возможности

### Соискатель

Соискатель может:

- зарегистрироваться на платформе;
- войти и выйти из аккаунта;
- создать и редактировать своё резюме;
- указать навыки, опыт, образование и желаемую зарплату;
- просматривать вакансии;
- искать и фильтровать вакансии;
- откликаться на вакансии;
- выбирать резюме при отклике;
- просматривать свои отклики;
- отслеживать статус отклика.

### Работодатель

Работодатель может:

- зарегистрироваться на платформе;
- создать компанию;
- создавать вакансии;
- редактировать и удалять только собственные вакансии;
- просматривать отклики на свои вакансии;
- изменять статус кандидата.

### Администратор

Администратор имеет доступ к Django Admin и может управлять данными платформы.

## Статусы откликов

Для откликов используются следующие статусы:

- Новый;
- На рассмотрении;
- Приглашён на собеседование;
- Отклонён;
- Принят.

На сайте реализованы:

## REST API

В проекте реализован REST API.

Основные endpoints:

```text
/api/companies/
/api/skills/
/api/vacancies/
/api/resumes/
/api/applications/
```

### JWT

Получение пары JWT-токенов:

```text
POST /api/token/
```

Обновление access-токена:

```text
POST /api/token/refresh/
```

### Swagger

Интерактивная документация API:

```text
/api/docs/
```

OpenAPI schema:

```text
/api/schema/
```

### Изменение статуса отклика

Работодатель может изменять статус отклика через бизнес-endpoint:

```text
PATCH /api/applications/{id}/status/
```

Пример:

```json
{
  "status": "accepted"
}
```

---

## Права доступа API

### Соискатель

Соискатель может:

- работать со своими резюме;
- просматривать свои отклики;
- создавать отклики;
- просматривать вакансии.

Соискатель не может:

- создавать компании;
- создавать вакансии;
- изменять статус отклика;
- изменять чужие данные.

### Работодатель

Работодатель может:

- создавать компании;
- управлять своими вакансиями;
- просматривать отклики на свои вакансии;
- изменять статус откликов;
- просматривать активные резюме.

Работодатель не может:

- создавать резюме;
- изменять чужие вакансии;
- работать с откликами на чужие вакансии.

---

## Бизнес-правила

В проекте реализованы следующие ограничения:

- один соискатель не может дважды откликнуться на одну вакансию;
- соискатель может использовать только собственное резюме;
- для отклика через API используется активное резюме;
- работодатель может редактировать только собственные вакансии;
- работодатель может изменять статус только откликов на собственные вакансии;
- зарплата не может быть отрицательной;
- зарплата `от` не может быть больше зарплаты `до`;
- права пользователей зависят от роли.

# Установка проекта

## 1. Клонировать репозиторий

```bash
git clone https://github.com/KonstantinMT/job-platform-diploma.git
```

Перейти в папку проекта:

```bash
cd job-platform-diploma
```

---

## 2. Создать виртуальное окружение

Windows:

```bash
python -m venv venv
```

Активировать виртуальное окружение:

```bash
venv\Scripts\activate
```

---

## 3. Установить зависимости

```bash
pip install -r requirements.txt
```

---

## 4. Создать PostgreSQL базу данных

Пример:

```sql
CREATE DATABASE job_platform_db;

CREATE USER job_platform_user
WITH PASSWORD 'your_password';

GRANT ALL PRIVILEGES
ON DATABASE job_platform_db
TO job_platform_user;
```

После этого необходимо подключиться к созданной базе и выполнить:

```sql
GRANT ALL
ON SCHEMA public
TO job_platform_user;
```

---

## 5. Создать файл `.env`

В папке с `manage.py` создать файл:

```text
.env
```

Пример содержимого:

```env
DB_NAME=job_platform_db
DB_USER=job_platform_user
DB_PASSWORD="your_password"
DB_HOST=localhost
DB_PORT=5432
SECRET_KEY="your_django_secret_key"
```

Файл `.env` содержит конфиденциальные данные и не должен добавляться в Git.

---

## 6. Выполнить миграции

```bash
python manage.py migrate
```

---

## 7. Создать администратора

```bash
python manage.py createsuperuser
```

---

## 8. Запустить сервер

```bash
python manage.py runserver
```

После запуска сайт доступен по адресу:

```text
http://127.0.0.1:8000/
```

Django Admin:

```text
http://127.0.0.1:8000/admin/
```

Swagger:

```text
http://127.0.0.1:8000/api/docs/
```
